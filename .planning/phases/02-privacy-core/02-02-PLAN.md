<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| detection core -> masking | Raw hit values are used locally only to replace and verify sensitive substrings. |
| masking -> diagnostics | Mask result metadata crosses to diagnostics; masked payload text must not be mixed into diagnostic summaries. |
| diagnostics -> stdout/JSON callers | Human/tool consumers receive sanitized metadata only. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-02-01 | Information Disclosure | `MaskResult` diagnostics | mitigate | Serializers consume sanitized fields and tests assert raw hit values are absent. |
| T-02-02-02 | Tampering | `verify_mask()` | mitigate | Verification checks original hit remnants and residual detections before marking output verified. |
| T-02-02-03 | Repudiation | incomplete masking status | mitigate | Return explicit `verification_status` and reason codes for pause/block decisions. |
| T-02-02-04 | Elevation of Privilege | reversible masking maps | mitigate | Do not create decrypt/deanonymization state per D-04 and MASK-03. |
</threat_model>
