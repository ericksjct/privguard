| cleanup CLI → stderr/stdout | Error and skip messages are written to the user/terminal. POL-04 requires these to contain paths and reason codes only, never file contents. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-05 | Information Disclosure | `_load_patterns` unguarded reopen (WR-01 target) | mitigate | Wrap the reopen in `try/except (OSError, tomllib.TOMLDecodeError)` routing through `_err` (sanitized: message + reason code only, never raw exception/contents — POL-04, ASVS V7). Currently a TOCTOU OSError escapes as an unhandled traceback (exit 1) that could leak a path/stack; the guard surfaces it as `[CLEANUP] error: pyproject.toml unreadable reason=pyproject_unreadable` with exit 2. |
| T-09-06 | Denial of Service / contract integrity | cleanup exit-code contract (D-14) | mitigate | WR-01 ensures the fail-closed exit-code contract (2 = misuse) holds even under the TOCTOU race, instead of an unhandled exit 1 that callers/CI may misinterpret as an apply-time OS error. |
| T-09-07 | Tampering | `_format_dry_run` fragile `.replace()` (WR-02 target) | mitigate | The string-substitution coupling could silently produce a malformed/misleading `[apply]` header if the dry-run literal changes, masking what is actually being deleted. Parameterizing the formatter removes the silent-regression surface; the 6 cleanup contract tests (sanitization asserts) stay green. |

The WR-01 fix is itself the primary security/robustness improvement of this phase: sanitized error
output (no raw path/exception leakage) and fail-closed exit-code integrity per D-14.
