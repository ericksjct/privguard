# Phase 999.3 Plan 01: Detection — 3 regex fixes em detection.py Summary

**One-liner:** Fixed three regex bugs in PATTERNS: RG suffix mandatory, BR_PHONE drops \b before DDD, BR_PLACA_OLD adds negative lookahead — plus 5 regression tests added, 146 tests pass.

## What Was Built

Three precision regex fixes in `privguard/detection.py` (the `PATTERNS` list) correcting false positives and missed detections found in the stress-test file `texto_com_pii.txt`:

1. **BR_RG suffix mandatory:** Changed `(?:-[\dXx])?` to `-[\dXx]` — the `?` made the digit suffix optional, allowing the `XX.XXX.XXX` prefix of a CNPJ to match as an RG. The suffix is now required.

2. **BR_PHONE \b removed before DDD:** Changed `\(?\b\d{2}` to `\(?\d{2}` — the word boundary between `55` and a DDD like `16` is not a true word boundary (both are `\w` chars), so `+5516988887777` was silently dropped. Removing `\b` restores the match.

3. **BR_PLACA_OLD negative lookahead:** Changed `\d{4}\b` to `\d{4}(?![-\d])\b` — without the lookahead, transaction IDs such as `TXN-2026-0315-887766` matched `0315` as a plate suffix. The lookahead rejects matches followed by `-` or another digit.

Five regression tests were added to `tests/test_detection.py` to lock each fix and its positive counterpart.
