<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Synthetic fixture -> package APIs | Test strings enter detection, masking, policy, diagnostics, CLI, and hook code as untrusted prompt/tool-like inputs. |
| Test scanner -> repository files | The source scanner reads only allowlisted safe text paths and must not cross into protected local data. |
| Hook stdin -> hook output | JSON payloads enter Claude hook adapters and may produce stdout/stderr/JSON additional context. |
| Failure path -> pytest output | Exceptions and assertion failures can expose strings if tests include raw values in messages or parameters. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01 | Information Disclosure | `tests/test_v1_regression_gate.py` scanner | mitigate | Use explicit allowlisted globs and `_is_excluded()` for `.env*`, `data_sensivel`, `.planning`, `.git`, caches, bytecode, and pytest temp cache paths. |
| T-05-02 | Information Disclosure | CLI/hook/diagnostic output assertions | mitigate | Apply one forbidden-output corpus to stdout, stderr, JSON, diagnostics, masked metadata, and selected failure messages. |
| T-05-03 | Information Disclosure | Claude hook payload tests | mitigate | Invoke hook entry points in process with synthetic JSON; assert sanitized reason codes and no raw prompt, command, path, token, or placeholder echoes. |
| T-05-04 | Information Disclosure | `redact()` / fail-closed exception paths | mitigate | Add exception-message hygiene checks and fail-closed policy assertions for unverified masking and unsupported capabilities. |
| T-05-05 | Spoofing | Codex compatibility claims | mitigate | Assert automatic masking rows remain absent unless verified outbound replacement proof exists; scan safe docs/source for unsupported positive claims. |
| T-05-06 | Tampering | Test-local overlap monkeypatch | mitigate | Limit monkeypatch to a single test using pytest `monkeypatch`, rely on package `detect()` behavior, and let pytest restore state. |
</threat_model>
