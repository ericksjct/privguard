<objective>
Close the fragmentation and concatenation evasion vectors (R5, R6, R10, R11) with ONE mechanism:
a denoised second pass gated by checksum. Removing injectable separators reassembles both a CPF
split across lines and a CPF concatenated in source code; requiring a passing checksum keeps
false positives bounded (~1 in 100 for CPF) so we do not flood users with noise.

This is the highest false-positive-risk plan in the phase. The FP corpus is the hard gate: a
fix that raises the FP rate is not shipped.

Findings targeted:
- R5: CPF fragmented across lines.
- R6: whitespace injected between digits.
- R10: string concatenation `"123.456" + ".789-09"`.
- R11: f-string concatenation.

Honest scope: only checksum-bearing kinds (CPF, CNPJ, CNH, titulo eleitor, PIS/PASEP, SUS,
credit card) benefit — a concatenated EMAIL or secret has no checksum to gate on and stays a
documented limitation. A client-side scanner cannot be adversarially complete; this raises the
cost of accidental and low-effort evasion, not a guarantee against deliberate obfuscation.
</objective>

<context>
Non-negotiables: synthetic fixtures only, derive vectors programmatically; commit via
`git commit -F <tempfile>`; the PII guard scans Bash, not Write/Edit.

Mechanism detail:
- After the normalized primary pass (from 11-02), build a denoised variant:
  `denoised = re.sub(r"""[\s'"+]+""", "", normalized_text)` — strips whitespace/newlines, single
  and double quotes, and plus signs. This reassembles both fragmentation and string concatenation.
- Rescan `denoised` with ONLY the checksum-bearing PatternEntry set (those whose `.validator` is
  not None AND kind in the checksum group). For each match, run the validator; keep only passers.
- Deduplicate against primary-pass hits (do not double-report a value already caught normally).
- Offset mapping: denoising changes positions non-trivially. Build a denoised→original index map
  the same way as 11-02 (record the original index of each surviving char). Map the hit span to
  [first_orig, last_orig+1]. If mapping is ambiguous, still emit the hit (forces block); mask_text
  may fail verification on such a span, which fail-closed BLOCKS — acceptable and safe.
- Use a distinct reason_code (e.g. "reassembled_checksum_valid") so diagnostics show why.

Do NOT emit non-checksum kinds from this pass — without a checksum their looser regexes on
separator-stripped text would produce many false positives (this is exactly what the FP corpus
guards against).
</context>
