<objective>
Close the encoded-secret evasion vectors (R7, R8, R9) with a decode-and-rescan stage: a secret
hidden in base64/hex/URL-encoding is a real, plausible-by-accident exfil path (copy-pasted
encoded config, a token embedded in a data URI). Gate on a high-confidence secret match in the
decoded content so ordinary encoded blobs (hashes, IDs, images) produce no hits.

Findings targeted:
- R7: base64-encoded secret passes through.
- R8: hex-encoded secret passes through.
- R9: URL/percent-encoded secret passes through.

Honest scope: single-layer decoding of RECOGNIZABLE secrets only. Double-encoding, encoded
numeric BR identifiers, and novel secret formats are out of reach and stay documented
limitations. This raises the cost of low-effort encoding, not a guarantee.
</objective>

<context>
Non-negotiables: synthetic fixtures only (the canonical SECRET_LOOKING/API-key style constants);
derive encoded variants programmatically (base64.b64encode(secret.encode()) etc.) in tests,
never hardcode; commit via `git commit -F <tempfile>`.

Mechanism detail:
- Candidate blob regexes (conservative, min length to avoid noise):
  base64  `\b[A-Za-z0-9+/]{24,}={0,2}\b`, hex `\b(?:[0-9a-fA-F]{2}){16,}\b`,
  percent/URL-encoded runs containing `%[0-9A-Fa-f]{2}`.
- For each candidate: decode single-layer (base64.b64decode with validate=True; bytes.fromhex;
  urllib.parse.unquote). Wrap each decode in try/except; skip on failure or if the result is not
  valid UTF-8.
- Rescan the decoded string with ONLY the high-score secret PatternEntries (score ≥ 0.95:
  API_KEY, AWS_KEY, TOKEN, JWT, DATABASE_URL, PASSWORD/SECRET/ENV assignments). Do NOT rescan for
  numeric BR identifiers — an arbitrary decoded byte run hits those far too easily.
- If a secret is found in decoded content, emit ONE Hit spanning the original encoded blob
  (start/end of the blob match), kind = the secret kind (or a dedicated kind like
  ENCODED_SECRET), reason_code e.g. "encoded_secret_<enc>". The point is to BLOCK the outbound
  encoded payload — exact sub-span inside the blob is not needed.
- Dedup against earlier passes; merge into the final hit list before threshold/overlap/sort.
</context>
