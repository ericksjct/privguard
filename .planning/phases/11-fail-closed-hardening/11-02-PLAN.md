<context>
Non-negotiables: synthetic fixtures only; derive hostile variants programmatically at runtime
(e.g. insert a ZWSP U+200B between digits via chr(0x200B), .translate() a confusable map)
rather than hardcoding new
PII literals — this is the pattern phase 10 already used in tests/test_evasion_adversarial.py.
Commit via `git commit -F <tempfile>`.

The offset-safety requirement is the crux. detect() (detection.py line ~285) returns Hit objects
whose start/end/value are consumed by masking (mask_text) and diagnostics. If normalization
changes string length and you scan the normalized string, offsets no longer map to the original.

Design constraint that makes this tractable: use ONLY length-preserving (1:1 translate) or
removal transforms, so an index map is trivial to build:
- Confusable digit map: str.translate() table mapping specific homoglyph codepoints → ASCII
  digit. 1:1, offsets preserved. Keep the table CONSERVATIVE — digit lookalikes only (e.g.
  Cyrillic Е/О/З-class only where they map to digits is nonsense; for DIGITS the real vectors
  are fullwidth ０-９ U+FF10-FF19, and any Cyrillic/Greek chars the phase-10 test actually used —
  read that test to see the exact codepoints it injects, and cover those). Do NOT map Latin
  letter homoglyphs broadly (that mangles legitimate text and spikes FP).
- Remove chars where unicodedata.category(ch) == "Cf" (format, includes ZWSP U+200B, ZWNJ,
  ZWJ, BOM U+FEFF, soft hyphen U+00AD) and == "Mn" (nonspacing combining marks).

Do NOT use full NFKC/NFKD normalize() on the whole string — it is length-changing (ligatures,
etc.) and would break the offset map for little threat-model benefit.
</context>
