<objective>
Add opt-in CPF leniency mode to the detection and masking engine.

Purpose: Formatted CPF strings (`DDD.DDD.DDD-DD`) with invalid checksums are currently silently ignored. Users running with synthetic or mistyped CPF data (e.g. during testing) cannot mask these values without modifying source data. Lenient mode closes this gap while keeping strict as the safe default.

- `privguard/detection.py` — three new module-level constants (`_lenient_default`, `_LENIENT_KINDS`, `_LENIENT_SCORES`), updated `detect()` and `analyze_text()` signatures
- `privguard/masking.py` — updated `mask_text()` signature with `lenient` parameter threaded to `detect()`
</objective>

```python
def detect(text: str, min_score: float = 0.6) -> list[Hit]:
    raw: list[Hit] = []
    for entry in PATTERNS:
        for m in entry.regex.finditer(text):
            value = m.group(0)
            # Skip hits whose checksum fails entirely — do NOT emit a
            # downgraded score that would shadow other kinds covering the
            # same span (e.g. BR_CPF failing checksum would block BR_CNH
            # and BR_PIS_PASEP from the same 11-digit value).
            if entry.validator and not entry.validator(value):
                continue                          # <- lenient branch goes here
            raw.append(Hit(entry.kind, m.start(), m.end(), value,
                           entry.score, entry.reason_code))

    raw = [h for h in raw if h.score >= min_score]
    raw.sort(key=lambda h: (-h.score, -(h.end - h.start), h.start))
    kept: list[Hit] = []
    for h in raw:
        if not any(not (h.end <= k.start or h.start >= k.end) for k in kept):
            kept.append(h)
    kept.sort(key=lambda h: h.start)
    return kept


def analyze_text(text: str, min_score: float = 0.6) -> DetectionReport:
    hits = tuple(detect(text, min_score=min_score))
    counts: dict[str, int] = {}
    for hit in hits:
        counts[hit.kind] = counts.get(hit.kind, 0) + 1
    return DetectionReport(hits=hits, counts=counts)
```

  ```python
      return os.environ.get("PII_GUARD_LENIENT", "").lower() in ("1", "true", "yes")

  _LENIENT_KINDS: frozenset[str] = frozenset({"BR_CPF"})

  _LENIENT_SCORES: dict[str, float] = {"BR_CPF": 0.75}
  ```

  Step 3 — Replace the current `detect()` signature and body. The new signature is:

  ```python
  def detect(
      text: str,
      min_score: float = 0.6,
      lenient: bool | None = None,
  ) -> list[Hit]:
      use_lenient = _lenient_default() if lenient is None else lenient
      raw: list[Hit] = []
      for entry in PATTERNS:
          for m in entry.regex.finditer(text):
              value = m.group(0)
              # Skip hits whose checksum fails entirely — do NOT emit a
              # downgraded score that would shadow other kinds covering the
              # same span (e.g. BR_CPF failing checksum would block BR_CNH
              # and BR_PIS_PASEP from the same 11-digit value).
              if entry.validator and not entry.validator(value):
                  if use_lenient and entry.kind in _LENIENT_KINDS:
                      # Formatted-only guard: bare 11-digit CPF must stay strict
                      # to avoid shadowing BR_CNH and BR_PIS_PASEP on same span.
                      if "." in value and "-" in value:
                          raw.append(Hit(
                              entry.kind, m.start(), m.end(), value,
                              _LENIENT_SCORES[entry.kind],
                              "lenient_pattern",
                          ))
                  continue
              raw.append(Hit(entry.kind, m.start(), m.end(), value,
                             entry.score, entry.reason_code))

      raw = [h for h in raw if h.score >= min_score]
      raw.sort(key=lambda h: (-h.score, -(h.end - h.start), h.start))
      kept: list[Hit] = []
      for h in raw:
          if not any(not (h.end <= k.start or h.start >= k.end) for k in kept):
              kept.append(h)
      kept.sort(key=lambda h: h.start)
      return kept
  ```

  CRITICAL: The `continue` statement must remain AFTER the lenient branch, not inside it. This prevents double-emitting: even when a lenient hit is appended, we still skip the strict `raw.append` below (because the validator failed).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| env → detection engine | `PII_GUARD_LENIENT` is read from the process environment; any process with write access to the environment can enable lenient mode |
| caller → detect() | Callers can pass `lenient=True` programmatically, bypassing the env-var default |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-999.4-01 | Information Disclosure | `detect()` lenient mode | accept | Lenient mode masks MORE data (reduces exfiltration risk), never less. False positives from lenient mode (masking a reference number that matches `DDD.DDD.DDD-DD`) are a usability concern, not a security concern: the user opted in. |
| T-999.4-02 | Tampering | `PII_GUARD_LENIENT` env var | accept | An attacker who can set env vars already has process-level access; this flag does not expand the attack surface. The flag enables MORE masking, so setting it adversarially harms usability, not privacy. |
| T-999.4-03 | Information Disclosure | Bare 11-digit CPF bypass | mitigate | The format guard (`"." in value and "-" in value`) prevents lenient mode from emitting bare 11-digit CPF hits, which would shadow valid BR_CNH and BR_PIS_PASEP detections on the same span. Without the guard, valid identifiers would be misclassified as CPF and potentially missed by downstream policy. Guard is enforced in the lenient branch of `detect()`. |
| T-999.4-04 | Information Disclosure | verify_mask() strict enforcement | mitigate | `verify_mask()` is intentionally NOT passed the `lenient` parameter. If verification were lenient, a masked text that still contained the raw value would pass; strict verification ensures `<BR_CPF>` replacement is confirmed. This is a defense-in-depth layer. |
| T-999.4-05 | Tampering | Score downgrade (0.75 vs 0.95) | accept | Lenient hits score below strict hits. The overlap resolution (score → length → position) ensures a valid strict hit always wins over a lenient hit on the same span. No risk of strict hits being demoted. |
</threat_model>
