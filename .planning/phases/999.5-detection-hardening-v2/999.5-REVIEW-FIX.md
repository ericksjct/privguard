## WR-01: Name hits bypass `min_score` filter — FIXED

**File:** `privguard/detection.py:315-317`

Moved the `min_score` filter to run **after** `_find_name_hits` appends name hits, so all hits (including name hits at score 0.58 or 0.65) are uniformly filtered by the caller-specified threshold.

```python
# Before (buggy)
raw = [h for h in raw if h.score >= min_score]
if use_detect_names:
    raw.extend(_find_name_hits(text))   # bypass

# After (fixed)
if use_detect_names:
    raw.extend(_find_name_hits(text))
raw = [h for h in raw if h.score >= min_score]  # filter after
```

**Side effect on tests:** `test_name_detection_first_only_score` was written against the old behavior (expected a 0.58-score hit to survive at default `min_score=0.6`). Updated it to call `detect(..., min_score=0.5)` so the first-name hit is observable; the docstring was updated to explain that score 0.58 is intentionally below the 0.6 default.

**Commits:**
- `fix(999.5): apply min_score filter after name hits to prevent bypass (WR-01)`

## WR-02: `verify_mask` re-scans without `detect_names` — FIXED

**File:** `privguard/masking.py:54-99`

Added `detect_names: bool | None = None` to `verify_mask`'s signature and propagated it into the `detect()` call inside the function. Updated `mask_text` to pass `detect_names` to `verify_mask` so the verification pass uses the same detector configuration as the original detection pass.

```python
# verify_mask — before
def verify_mask(original_text, masked_text, hits, min_score=0.6):
    ...
    residual_hits = [hit for hit in detect(masked_text, min_score=min_score) ...]

# verify_mask — after
def verify_mask(original_text, masked_text, hits, min_score=0.6, detect_names=None):
    ...
    residual_hits = [hit for hit in detect(masked_text, min_score=min_score, detect_names=detect_names) ...]

# mask_text call site — after
verified, verification_reasons = verify_mask(
    text, masked_text, selected_hits, min_score=min_score, detect_names=detect_names
)
```

**Commits:**
- `fix(999.5): propagate detect_names through verify_mask to close verification gap (WR-02)`
