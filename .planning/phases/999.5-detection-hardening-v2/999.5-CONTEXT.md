# Phase 999.5: Detection Hardening v2 - Context

**Gathered:** 2026-05-22
**Status:** Ready for planning

<domain>
## Phase Boundary

Close five specific detection gaps found via stress-test with `texto_com_pii.txt`, all changes contained within `privguard/detection.py` and the CLI layer:
1. CEP dot variant (`14.025-580`) not detected by current regex
2. CNPJ leniency for synthetic/invalid-checksum CNPJs (opt-in, mirrors CPF leniency)
3. IBAN false positive — space-separated IBANs generate `<BR_PHONE>` hits on the inner digit span
4. Brazilian name detection (opt-in, IBGE 2010 census data, separate `detect_names()` function)
5. Barcode false positives — `BR_PIS_PASEP` and `BR_PHONE` matching inside boleto sequences

No new CLI commands. Existing `scan`/`mask`/`policy-check` commands gain new flags where needed.

</domain>

<decisions>
## Implementation Decisions

### CEP Dot Variant
- **D-01:** Extend `BR_CEP` regex to cover `NN.NNN-NNN` format in addition to the current `\d{5}-?\d{3}`. No change to score or validator.

### CNPJ Leniency
- **D-02:** The global `PII_GUARD_LENIENT` env var activates leniency for **both** CPF and CNPJ together. No separate `PII_GUARD_LENIENT_CNPJ` flag. Adding `"BR_CNPJ"` to `_LENIENT_KINDS` with the appropriate lenient score is all that's needed.
- **D-03:** Bare 14-digit CNPJs stay **strict** even in lenient mode — only formatted CNPJs (`XX.XXX.XXX/XXXX-XX`) get lenient treatment. This mirrors the CPF decision (bare 11-digit stays strict) and prevents false-positive shadowing of other kinds on raw digit spans.

### IBAN False Positive Fix
- **D-04:** Fix by extending the IBAN pattern to match the **space-separated canonical print format** (`CC99 XXXX XXXX ... ` with strict 4-char groups). The full IBAN span (score 0.90) wins over any inner `BR_PHONE` match (score 0.76) via the existing overlap/priority logic in `detect()`. No guard change to `BR_PHONE`.
- **D-05:** The space-separated IBAN variant uses strict 4-char groups (not permissive whitespace). Pattern covers country code (2 uppercase letters) + check digits (2 decimal) + BBAN in 4-char groups up to 34 total chars.

### Brazilian Name Detection
- **D-06:** Name list lives as a **static data file** inside the package (`privguard/data/names.txt` or similar). Requires `package_data` / `importlib.resources` wiring in `pyproject.toml`. Keeps `detection.py` slim and avoids embedding large string literals.
- **D-07:** Opt-in via **`PII_GUARD_DETECT_NAMES=true`** (env var) and **`--detect-names`** CLI flag. Exact names from the backlog spec — no variation.
- **D-08:** Full **tiered scoring** as specified: 0.58 (first name alone), 0.65 (surname alone), 0.72 (first name + surname consecutive). Not a flat score.
- **D-09:** Implemented as a separate `detect_names()` function called inside `detect()` when name detection is enabled. Source data: IBGE 2010 Census (~1,500 first names + ~300 surnames, ~95% population coverage). Tokenization by space/punctuation + frozenset O(1) lookup.

### Barcode False Positives
- **D-10:** Add a `BR_BOLETO` pattern to `PATTERNS` covering **both** raw digit format (44–47 consecutive digits) and the formatted human-readable boleto line (groups separated by dots and spaces, e.g. `XXXXX.XXXXX XXXXX.XXXXXX XXXXX.XXXXXX X XXXXXXXXXXXXXXXXXX`). Assign a score high enough (≥ 0.90) to win over inner `BR_PIS_PASEP` and `BR_PHONE` matches via the existing overlap logic. No changes to those patterns themselves.

### Claude's Discretion
- Exact score for `BR_BOLETO` (≥ 0.90 is the floor; planner/executor may use 0.92 or similar)
- Exact filename/format of the names data file (`names.txt` vs. `names.json`, first-names vs. combined)
- Whether to add `--detect-names` to `scan` only or to `mask` and `policy-check` as well (can follow whatever makes most sense for the CLI symmetry)
- IBGE data source: static snapshot vs. SIDRA API call at dev time (the file itself must be committed; no runtime network call)

</decisions>

### Established Patterns
- Score-based overlap resolution: higher score wins, ties broken by span length then start position
- Formatted-only guard in lenient mode: check for punctuation chars (`.` `-` `/`) before emitting a lenient hit — `BR_CNPJ` needs the same guard (requires `.` and `/`)
- All patterns use `re.compile` at module import, not at call time

- `CLI --lenient` flag → `detect(lenient=True)` — `--detect-names` should follow the same pattern → `detect(detect_names=True)`
