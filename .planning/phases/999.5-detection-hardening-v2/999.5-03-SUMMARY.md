## Summary

Implemented Brazilian name detection as an opt-in feature. Two tasks completed:
1. Name detection infrastructure in `detection.py`
2. `detect_names` kwarg wired through `masking.py` and `--detect-names` CLI flags in `cli.py`

## What Was Built

### detection.py
- `_NAMES_DATA` — importlib.resources path to `privguard/data/`
- `_TOKEN_RE` — `[^\W\d_]+` Unicode word tokenizer
- `_load_name_sets()` — `@lru_cache(maxsize=1)` loader returning `(frozenset[first_names], frozenset[surnames])`
- `_detect_names_default()` — reads `PII_GUARD_DETECT_NAMES` env var
- `_find_name_hits(text)` — token-pair scanner emitting `BR_NAME` hits:
  - first+surname or surname+first → score 0.72, reason_code `name_fullname`
  - first name alone → score 0.58, reason_code `name_first`
  - surname alone → score 0.65, reason_code `name_surname`
- `detect()` extended with `detect_names: bool | None = None` param
- `analyze_text()` extended with `detect_names: bool | None = None` param

### masking.py
- `mask_text()` extended with `detect_names: bool | None = None`, forwarded to `detect()`

### cli.py
- `--detect-names` flag added to `scan`, `mask`, `policy-check` subparsers
- `detect_names = True if args.detect_names else None` in all three handlers

## Key Implementation Note

Name hits bypass the `min_score >= 0.6` filter in `detect()` because `name_first` scores 0.58. Name hits are added after the score filter but before the overlap sort, so they participate in overlap deduplication normally.

## Deviations

- **min_score bypass**: Name hits inserted after the score filter (not before as written in plan). Required because `name_first` score (0.58) is below default `min_score=0.6`. All must_have behaviors verified — scores are preserved as specified.
