<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| untrusted text -> detector | User prompts and shell commands are scanned locally and may contain sensitive values. |
| detector internals -> diagnostics | `Hit.value` is needed internally for masking but must not cross into logs or hook messages. |
| path strings -> path policy | Protected paths must be classified without opening files. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-02-01 | Information Disclosure | `privguard.policy.summarize_hits` | mitigate | Return only `kind`, `start`, `end`, and `score`; omit `Hit.value` by construction. |
| T-01-02-02 | Information Disclosure | implementation/tests | mitigate | Use only synthetic strings and path literals; do not open `.env` or `data_sensivel/**`. |
| T-01-02-03 | Denial of Service | package imports | mitigate | Keep detection/masking/policy stdlib-only; no Presidio/spaCy imports in default modules. |
| T-01-02-04 | Tampering | policy extraction | mitigate | Preserve exact sensitive path regex categories from `hooks/pre_tool_guard.py` so Phase 1 does not weaken path classification. |
</threat_model>
